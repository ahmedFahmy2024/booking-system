# Booking system — agent rules

Single repository. React + Vite frontend in `apps/web`, Hono API in `apps/api`, Neon Postgres behind the API only.

## Skills

Project skills live in `.agents/skills` and are listed in [`docs/SKILLS.md`](docs/SKILLS.md) with what each one does and when to use it. Load the relevant skill before working on its area: `vite` / `feature-sliced-design` / `tanstack-router` / `tanstack-query` / `tanstack-devtools` for `apps/web`, `hono` / `drizzle` / `neon-drizzle` / `neon-postgres` for `apps/api` and the database, `vitest` for tests, and `agent-browser` for browser QA.

## Layout

```text
apps/web/src/
  app/        # entry point, router, providers — composes features
    routes/       # file-based routes (createFileRoute)
    providers/    # QueryClientProvider + RouterProvider + devtools
    ui/           # app-wide layout and error components
    routeTree.gen.ts  # generated by @tanstack/router-plugin — never edit by hand
  features/   # feature UI, hooks, HTTP calls (one folder per feature)
  shared/     # reusable UI and utilities
apps/api/src/
  app.ts      # creates the Hono app and mounts route groups with app.route()
  features/   # route groups, business logic, calls into db/
  db/         # Neon connection, schema, migrations
drizzle/      # generated SQL migrations (apps/api)
```

## Import boundaries

- `@/` is scoped to `apps/web/src` only (configured in `vite.config.ts` and `tsconfig.app.json`). Use `@/features/<name>` only through that feature's public `index.ts`.
- Inside a feature, use relative imports. A feature may import from `shared/`, but never from another feature's internals.
- `app/` composes feature-to-feature interactions first. Move shared code into `shared/` only when it has a genuinely reusable purpose.
- `shared/` may import other shared modules and external libraries, never `app/` or `features/`.
- React reaches Hono over HTTP. Never import `@neondatabase/serverless`, `drizzle-orm`, or anything from `apps/api/src/db` into `apps/web`. `DATABASE_URL` stays on the API side.
- API route groups live under `apps/api/src/features/<name>` and expose a Hono router; `app.ts` mounts them.
- Server-only imports (`@neondatabase/serverless`, `drizzle-orm`, `apps/api/src/db`) are blocked in `apps/web` by `no-restricted-imports` in `apps/web/.oxlintrc.json`. Both apps have their own `.oxlintrc.json` and a `lint` script. Cross-feature imports through another feature's internals are a convention only; Oxlint cannot express that rule yet.
- CI (`.github/workflows/ci.yml`) runs lint, typecheck, tests, and builds for both apps. Route tests mock `getDb()`, so CI needs no `DATABASE_URL`.

## Frontend → API

`apps/web` calls Hono over HTTP. In dev, Vite proxies `/api/*` to `http://localhost:3000` and strips the prefix; set `VITE_API_URL` for other environments (see `apps/web/.env.example`). Booking UI lives in `apps/web/src/features/bookings` and is imported only through its public `index.ts`.

Playwright E2E (`npm run test:e2e` from `apps/web`) boots both apps itself. The API runs with `apps/api/.env.test` pointing at an isolated Neon database; create it once with `CREATE DATABASE booking_system_test`, then migrate and seed it with `DATABASE_URL` from that file. `.env.test` is gitignored — CI needs no database secret unless the E2E job is enabled.

## Frontend routing & server state

`apps/web` uses TanStack Router (file-based) and TanStack Query, loaded via the `tanstack-router` / `tanstack-query` skills.

- Routes live in `src/app/routes/`; `src/app/routeTree.gen.ts` is generated by `@tanstack/router-plugin` and must never be edited by hand.
- One `QueryClient` is created in `app/providers/` and passed to the router through its context.
- Routes prime the cache in `loader` with `queryClient.query({ ...queryOptions, staleTime: 'static' })`; components read the same options with `useSuspenseQuery`. `ensureQueryData` and `prefetchQuery` are deprecated in current TanStack Query — do not reintroduce them.
- Error components using `useSuspenseQuery` must reset `useQueryErrorResetBoundary()` and retry via `router.invalidate()` (see `app/ui/route-error.tsx`).

## Source verification in code review (opensrc)

`opensrc` (installed globally; install with `npm install -g opensrc`) caches dependency source at `~/.opensrc/`. It is the source of truth when reviewing or changing how we call a library — types alone are not enough, read the implementation and the bundled docs.

```powershell
# Progress goes to stderr, the path to stdout — safe to assign in a subshell.
$querySrc = opensrc path @tanstack/react-query
$routerSrc = opensrc path @tanstack/react-router

Get-ChildItem "$querySrc\docs\framework\react\guides"
grep -r "deprecated" "$querySrc\packages\query-core\src"
Select-String -Path "$routerSrc\docs\router\integrations\query.md" -Pattern "queryClient.query"
```

Rules:

- `opensrc path` resolves the version actually installed (checks `node_modules` and lockfiles), so cached source matches this project. Cached results return instantly.
- If the npm registry lookup fails (e.g. `error decoding response body`), fall back to the GitHub registry with `opensrc path TanStack/query` or `opensrc path TanStack/router`.
- During code review, verify any claim about a library API against the cached source and its `docs/` folder before changing code. Check `@deprecated` annotations and migration guides first — do not rely on memory or third-party posts.
- `rg` is not installed on this machine; use `grep` or PowerShell `Select-String` for searching cached source.
- Never edit files under `~/.opensrc/` — it is a read-only cache. Set `OPENSRC_HOME` to override the location.

## Commands

Run from each app directory:

```powershell
# apps/web
npm run dev
npm run build
npm run lint

# apps/api
npm run dev
npm run build
npm run db:generate   # generate SQL migration after schema changes
npm run db:migrate    # apply migrations (needs DATABASE_URL)
npm run db:push       # quick schema sync for local development
npm run db:seed       # idempotent seed of services (needs DATABASE_URL)
```

Copy `apps/api/.env.example` to `apps/api/.env` and set the Neon `DATABASE_URL` before running DB commands.
